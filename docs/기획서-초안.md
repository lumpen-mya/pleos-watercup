# 찰랑: 물컵 챌린지 — 기획서 초안

접수양식 `02 앱 프로젝트 소개`의 1~7번 칸에 그대로 들어가는 내용. 개인정보는 넣지 않음.
`[확인]` 표시는 제출 전에 직접 확인하거나 정해야 하는 부분 (작성본 DOCX에는 들어가지 않음).

앱명 / 프로젝트명: **찰랑: 물컵 챌린지**

---

## 1. 앱 한 줄 소개

대시보드 위 가상의 물 한 컵으로 "뒷자리 사람이 편한 운전"을 보여 주고, 물을 쏟게 만든 조작을 차량 신호로 짚어 음성으로 알려 주는 동승자 승차감 코치.

## 2. 기획 배경

**주목한 불편: 멀미는 운전자가 아니라 동승자가 겪는다**

- 운전자는 앞 상황을 보고 몸이 먼저 대비하지만, 뒷좌석의 아이·어르신·반려동물·택시 승객은 차의 움직임을 예측하지 못한다. 같은 급제동이라도 동승자가 훨씬 크게 느낀다.
- 전기차에서는 이 불편이 더 자주 이야기된다. 가속 페달에서 발만 떼도 감속이 걸리는 회생제동 때문에 전기차 택시에서 멀미를 호소하는 승객이 많고, 일부 승객은 전기차 탑승을 꺼린다는 보도가 있다(코메디닷컴, 2024년 3월).
- 대상은 이미 크다. 국내 전기차 누적 등록은 2026년 6월 말 109만 5천여 대로 처음 100만 대를 넘었고(국토교통부), 2021~2023년 새로 등록된 택시 11만 1,583대 가운데 전기택시가 3만 3,400대로 약 30%를 차지했다(한국자동차모빌리티산업협회).

**왜 해결되지 않았나**

- 운전자는 자기 운전이 불편한지 알 방법이 없다. 동승자는 말하기 어렵고, 택시 승객은 말없이 다음 호출에서 전기차를 피한다.
- 기존 안전운전 점수는 과속·급가속 횟수를 숫자로 보여 줄 뿐, "어느 조작이 사람을 불편하게 했는지"와 "어떻게 고치면 되는지"는 알려 주지 않는다.
- 같은 차, 같은 길에서도 운전 습관에 따라 승차감이 크게 달라진다. 습관은 보여 주면 바뀐다. 필요한 것은 한눈에 이해되고, 원인을 짚어 주고, 운전을 방해하지 않는 피드백이다.

## 3. 앱 주요 기능 및 차량 특화 요소

**핵심 기능**

1. 물컵 화면 — 주행 중 화면에는 물이 담긴 컵 하나와 쏟은 양, 짧은 한마디 안내만 보인다. 감속·가속·조향에 따라 물이 출렁이고 한계를 넘으면 넘친다. 글을 읽지 않아도 한눈에 상태를 안다.
2. 원인 짚기 — 물이 넘친 순간의 차량 신호로 원인을 기본 네 가지로 구분하고, 길 안내 중에는 과속방지턱을 더한다.
   - 급제동 (브레이크 페달을 밟은 급감속)
   - 가속 페달 급히 떼기 (페달을 밟지 않은 감속, 회생제동)
   - 급가속
   - 급핸들 (방향지시등을 켜지 않은 경우 따로 표시)
   - 과속방지턱 (길 안내 중에만. 시속 30km 넘게 지나면 쏟은 것으로 센다. 30km/h는 초기값)
3. 음성 코칭 — 넘친 직후 짧은 한마디만 한다("정지 직전에 브레이크를 살짝 풀어 주세요"). 화면을 보지 않아도 된다.
4. 도착 리뷰 — P단에 넣으면 주행 거리·시간, 쏟은 횟수와 원인별 집계, 가장 많은 원인에 대한 조언을 한 화면과 음성으로 정리한다. "지난 주행보다 4번 줄었어요"처럼 지난 주행과 비교해 준다.
5. 케어 주행 — 뒷좌석 탑승이 감지될 때만 주행 중 음성 코칭을 한다. 혼자 탈 때는 주행 중에는 말없이 기록만 하고, 도착 리뷰만 음성으로 들려준다.
6. 동승자별 민감도 — 정차 중에 "아이·반려동물 / 어른 / 혼자" 세 단계로 고른다. 기본값은 승차감 문헌의 가속도 한계(약 1.5 / 2.0 / 3.0 m/s²)에 맞췄다.
7. 예고 안내 — 길 안내 중이면 다음 회전 지점 앞에서 "곧 우회전, 미리 속도를 줄여 주세요"로 먼저 알려 준다. 빠를수록 더 멀리서 알려 감속할 시간을 준다. 과속방지턱 앞에서도 같은 방식으로 알린다.
8. 말로 물어보기 — 정차 중에 "오늘 어땠어?", "왜 쏟았어?"라고 물으면 최근 주행 기록으로 답한다. 화면을 읽지 않아도 된다.
9. 동승자 확인으로 기준 맞추기 (선택) — 도착 후 "같이 탄 분은 어땠나요?"에 "괜찮았어요 / 불편했어요"로 답하면 다음 주행의 넘침 기준이 조금씩 바뀐다. 사람마다 불편을 느끼는 정도가 달라서다. 대기 화면에서 "기본값으로 복원"으로 언제든 되돌린다.
10. 주행 체크 — 도착 리뷰에 승차감 외의 기본기를 한 줄씩 정리한다. 신호가 들어오는 항목만 보인다.
   - 차선을 바꿀 때 방향지시등을 켰는지 (속도와 핸들 각도로 차선 변경을 추정)
   - 길 안내 중: 도로 제한속도 초과 시간과 최고 초과 속도
11. 운전에 방해되지 않는 사용 — 내비를 보는 동안에도 기록과 음성 코칭이 이어진다(백그라운드 동작). 내비와 나란히 띄우는 분할 화면처럼 창이 좁아지면 컵과 숫자, 짧은 한마디만 남는 작은 화면으로 바뀐다. 내비 음성 안내가 나오는 동안에는 코칭 음성을 최대 6초 미뤘다가 끝난 뒤 말하고, 그보다 늦어지면 생략한다(구현했으나 확인은 2차 개발).
12. 나아지는 모습 — 대기 화면에 주행별 쏟은 횟수 막대와 "그 전 3번보다 평균 2번 줄었어요" 같은 한 줄을 보여 준다.

**차량에서만 가능한 이유 (모바일 대비)**

- 휴대폰은 흔들림만 안다. 차는 "왜" 흔들렸는지 안다. 브레이크 페달, 핸들 각도, 기어, 방향지시등을 직접 읽어 "브레이크를 밟아서"인지 "페달을 떼서(회생제동)"인지 구분하는 것은 차량 앱만 할 수 있다. 이 구분이 있어야 "가속 페달은 천천히 떼어 주세요" 같은 원인별 조언이 나오고, 2차 개발에서는 "회생제동 단계를 낮춰 보세요" 같은 차량 설정 조언으로 넓힐 수 있다.
- 휴대폰은 거치 위치·각도에 따라 값이 달라지고 주행마다 앱을 챙겨야 한다. 차량 앱은 한 번 켜 두면 백그라운드에 남아, 이후에는 화면을 보지 않아도 기어를 D에 넣는 순간 기록을 시작하고 P에 넣으면 리뷰로 넘어간다. 앱을 완전히 닫으면 함께 끝난다.
- 누가 탔는지(뒷좌석 탑승)를 알기 때문에 동승자가 있을 때만 개입한다.
- 주행 중에는 소리와 컵 하나, 정차 후에는 자세한 화면이라는 주행·정차 맥락 구분을 차량 상태로 정확히 한다.

**기존 운전 점수 앱과의 차이**

- 목적이 연비나 사고 위험이 아니라 동승자 케어다. 흔들림의 크기만 재는 데서 그치지 않고 차량 신호로 원인을 짚어 고칠 방법까지 말하며, 뒷좌석 탑승 감지와 음성 코칭으로 운전자가 화면을 보지 않아도 동작한다.
- 안전운전 점수 앱이 "얼마나 위험했나"를 점수로 매긴다면, 본 앱은 "누가 불편했고 무엇을 고치면 되나"를 물 한 컵으로 보여 준다.

## 4. 주요 사용 시나리오

**시나리오 A — 아이를 태운 주말 이동 (가족)**

1. 출발 전 앱을 켜고 대기 화면에서 "아이·반려동물"을 고른다. 아이를 카시트에 태우고 기어를 D에 넣으면 물컵이 뜨고, 뒷좌석 탑승이 감지되어 케어 주행이 켜진다.
2. 신호 앞에서 평소처럼 브레이크를 밟자 물이 넘치고 "정지 직전에 브레이크를 살짝 풀어 주세요"라는 한마디가 나온다.
3. 길 안내가 우회전에 가까워지자 앱이 먼저 "곧 우회전, 미리 속도를 줄여 주세요"라고 말한다. 이번엔 물이 넘치지 않는다.
4. 도착해 P단에 넣으면 "2번 쏟았어요. 지난 주행보다 3번 줄었어요"라는 리뷰가 나온다. 아이가 "오늘은 안 쏟았어?" 하고 먼저 묻는 가족의 대화가 된다.

**시나리오 B — 전기차 택시·호출 차량 기사 (업무)**

1. 근무 시작 때 앱을 한 번 켜 두면, 이후에는 내비를 보는 동안에도 승객을 태우고 기어를 D에 넣을 때마다 기록이 시작된다. 주행 중 화면은 물컵만 보이고 음성은 넘친 직후 한 번만 나온다.
2. 운행을 마치면 "가장 많은 원인은 가속 페달 급히 떼기, 5번이에요. 가속 페달은 천천히 떼어 주세요"처럼 원인별 리뷰를 받는다. 회생제동 습관이 문제였음을 처음 알게 된다.
3. 최근 주행 기록으로 변화를 확인한다. 운수사·플랫폼이 이를 기사 교육과 "편안한 차량" 인증에 쓰는 것은 확대 계획이다. (지금 앱은 기록을 기기 밖으로 보내지 않고 사업자용 리포트도 아직 없으며, 화면 목업은 저장소 `docs/사업자-리포트-목업.md`에 있다)

**시나리오 C — 어르신·반려동물 동승, 초보 운전자**

- 병원 가는 길의 어르신, 이동장 안의 반려동물처럼 말로 불편을 표현하기 어려운 동승자를 태울 때 쓴다.
- 초보 운전자는 "부드럽게 운전해"라는 막연한 조언 대신 물컵이라는 눈에 보이는 목표를 얻는다.

## 5. 개발 계획

**구현 환경과 현재 상태**

- Kotlin + Jetpack Compose, minSdk 28. Pleos Connect Emulator(API 34, v2.1.0)와 Virtual Console로 검증
- 차량 신호 수집 → 승차감 엔진(물 출렁임 계산·넘침 판정·원인 분류) → 화면·음성 출력의 3단 구조. 주행 기록은 기기 내부에만 저장
- 1차 접수 시점에 핵심 흐름이 에뮬레이터에서 동작한다: 주행 중 물컵, 기본 원인 4종 분류, P단 도착 리뷰, 주행 기록 저장과 지난 주행 비교, 민감도 3단계, 뒷좌석 탑승 감지. Virtual Console로 급가속·회생제동·급조향·급제동을 넣어 네 원인이 모두 구분되고, 부드러운 주행은 "한 방울도 쏟지 않음"으로 판정되는 것을 확인했다. (거친 주행은 시연 영상, 부드러운 주행은 첨부 화면 참고) 음성 코칭과 도착 리뷰 음성은 오디오를 켠 에뮬레이터에서 재생 시작·완료를 로그로 확인했고, 정차 중 음성 질문은 듣기 시작까지 확인했다. 음성 인식 결과와 내비 음성 겹침 방지는 확인하지 못해 2차 개발에서 확인한다.
- 내비 예고 안내는 NaviHelper 연동과 예고 시점 판단까지 구현했다. 에뮬레이터에서 회전 안내 조회가 내비 서비스까지 전달되는 것을 확인했고, 실제 경로 안내 상태에서의 검증은 2차 개발에서 한다.
- 승차감 엔진(물 출렁임·원인 분류), 예고 시점 판단, 음성 질문 응답, 동승자 확인 기준 조절, 차선 변경 추정, 과속방지턱·제한속도 판정, 추세는 단위 테스트 40건으로 검증한다. 과속방지턱 예고와 제한속도 초과 시간 집계는 구현했지만 길 안내 중에만 값이 들어와 판정 로직을 단위 테스트로 검증했고, 실제 경로에서의 확인은 2차 개발에서 한다.

**SDK / API 사용 계획**

| SDK | 사용 API | 용도 |
|---|---|---|
| Vehicle | Brake `registerBrakePedalStatus` | 브레이크 페달 밟음 여부 → 페달 제동과 회생제동 구분 (구현) |
| Vehicle | SteeringWheel `registerSteeringWheelAngle` | 핸들 각도 → 횡방향 출렁임, 급조향 판정 (구현) |
| Vehicle | Gear `registerGearSelection` | D단 주행 시작 / P단 도착 리뷰 전환 (구현) |
| Vehicle | Seat `registerSeatOccupancy` | 뒷좌석 탑승 감지 → 케어 주행 (구현) |
| Vehicle | TurnSignal `registerTurnSignalState` | 방향지시등 없는 급조향 표시 (구현) |
| TextToSpeech | `speak` 온디바이스 모드 | 주행 중 한마디 코칭, 도착 리뷰 낭독 (구현) |
| Android Automotive Car API | `PERF_VEHICLE_SPEED` | 차량 속도 → 가감속 계산. Vehicle SDK에 속도 API가 없어 표준 API 사용 (구현) |
| NaviHelper | `getTBTInfo` 회전 안내 | 다음 회전 지점 앞 예고 안내 (구현, 경로 안내 상태 검증은 2차) |
| SpeechToText | `request` 온디바이스 모드 | 정차 중 "오늘 어땠어?" 음성 질문 (구현) |
| NaviHelper | `onCurrentRoadSpeedLimit` 도로 제한속도, `onCautionPointInfo` 과속방지턱 | 제한속도 초과 시간 집계, 과속방지턱 예고·통과 속도 판정 (구현, 실경로 검증은 2차) |
| NaviHelper | 목적지 도착 이벤트 | 도착 시 리뷰 (2차 개발) |
| FusedLocation | `registerFusedLocationCallback` | 어느 구간에서 쏟았는지 위치 기록 (2차 개발) |
| Vehicle | DrivingMode 주행 모드·크루즈 상태, Odometer 트립 | 회생제동·주행 모드 조언, 주행 단위 집계 (2차 개발) |

- 신호마다 등록을 따로 감싸 두어, 차종이 지원하지 않거나 등록에 실패한 신호만 빠지고 나머지는 그대로 동작한다. 대기 화면에는 아직 값을 받지 못한 신호 이름을 보여 주고, 모두 받으면 "차량과 연결됐어요"만 표시한다. 도메인별 지원 여부를 먼저 조회해 지원하지 않는 원인 분류를 끄는 방식은 2차 개발에서 더한다.
- 조회 권한만 선언한다(차량 제어 권한 없음). 승인 범위가 좁아 심사·입점 부담이 작다.

**개발 범위와 일정**

| 단계 | 기간 | 범위 |
|---|---|---|
| 1차 접수 | ~11/15 | 구현 완료: 물컵 화면, 원인 분류(기본 4종 + 과속방지턱), 음성 코칭, 도착 리뷰, 기록·비교, 민감도, 탑승 감지, 음성 질문, 내비 예고 연동, 동승자 확인 기준 조절, 주행 체크, 시연 영상 |
| 2차 PT 전 | ~12/2 | 경로 안내 상태에서 예고 안내 검증, 과속방지턱·제한속도 실경로 검증, 음성 인식 결과·내비 음성 겹침 방지 확인, 구간 기록, 주간 리포트, 실차 주행 데이터로 넘침 기준 보정, 주행 규제 대응(CarUxRestrictions 연동) 점검, 차종별 지원 여부 조회 |
| 전시 준비 | ~2027.01 | 구동 안정화, 차종별 지원 여부 대응 |

**주요 과제와 대응**

- 주행 중 주의 분산: 주행 중에도 화면이 보여야 하므로 주행 중 사용 가능(distractionOptimized) 앱으로 선언했다. 주행 화면에는 조작 요소·글자 입력·영상이 없고 컵과 숫자, 짧은 한마디 안내만 둔다. 민감도 선택, 기준 복원, 음성 질문, 동승자 답은 정차 중 화면(대기·도착 리뷰)에서만 받는다. 차량의 주행 중 UI 제한 상태(CarUxRestrictions)를 읽어 반영하는 것은 2차 개발 계획이다. 게임·미디어가 아니라 운전 코칭 앱으로 설계한다.
- 주행 중 화면 표시가 허용되지 않는 차종·지역에서는 주행 중에는 음성만 내고 정차 후 리뷰를 보여 주는 방식으로 핵심 가치를 유지한다.
- 넘침 기준: 공개된 승차감·교통공학 자료 22건에서 뽑은 수치 46건을 출처에서 다시 확인해 기본값을 정했다(일부는 초록·2차 인용 수준 확인). 서서히 걸 때 기준으로 아이·반려동물 약 1.55 m/s²(승차감 한계 0.15 g), 어른 약 2.0 m/s²(앉은 승객 쾌적 한계), 혼자 약 3.0 m/s²(교통공학의 편안한 감속)에서 넘친다. 갑자기 걸면 이보다 약 30% 낮은 값에서 넘친다. 아이·반려동물 전용 연구는 찾지 못해 그 값은 설계 선택이며, 개인차는 동승자 확인 기능으로 보정한다. 근거 정리는 저장소 `docs/넘침-기준-근거.md`에 있다.
- 음성 빈도: 넘침·차선 변경 안내는 직후 한 번만 말하고 8초 안에는 다시 말하지 않는다. 내비 음성 안내가 나오는 동안에는 최대 6초 미뤘다가 끝난 뒤 말하고, 그보다 늦어지면 생략한다(구현했으나 확인은 2차 개발).

## 6. 기대효과 및 발전 가능성

**사용자 가치**

- 동승자: 멀미·불안 감소. 말하지 않아도 운전이 부드러워진다.
- 운전자: 자기 운전을 처음으로 "승객 입장"에서 보고, 무엇을 고치면 되는지 안다. 부드러운 운전은 전비·연비와 브레이크 소모에도 유리하다.
- 완성차·플랫폼: "전기차는 멀미 난다"는 인식을 운전 습관 개선으로 풀어 가는 수단.

**타깃 고객**

1. 아이·어르신·반려동물을 자주 태우는 가족 운전자 (핵심)
2. 전기차 택시·호출 차량 기사, 법인 의전·셔틀 기사
3. 초보 운전자와 운전 연수

**시장 전제와 성과 지표**

- 전제: Pleos Connect는 2026년 5월 출시 예정으로 발표된 더 뉴 그랜저에 처음 적용하고 2030년까지 약 2천만 대에 적용할 계획이다(현대자동차그룹, 2026년 4월 발표). 국내 전기차 누적 등록은 2026년 6월 말 109만 5천여 대다(국토교통부, 2026년 7월 발표).
- 설치·활성 사용자 수는 아직 근거가 되는 탑재 대수와 설치율 자료가 없어 숫자로 제시하지 않는다. 계산 방식만 정해 두고, 탑재 대수가 공개되고 1차 배포 데이터가 생기면 채운다.
  - 설치 수 = 국내 Pleos Connect 탑재 차량 수 × 설치율 (둘 다 가정, 미정)
  - 월간 활성 사용자 = 설치 수 × 한 달에 한 번 이상 주행 기록이 생긴 비율 (가정, 미정)
  - 지금 앱은 기록을 기기 안에만 두고 전송하지 않아 활성 비율을 잴 수 없다. 재려면 사용자 동의를 받은 기록 수집을 새로 개발해야 한다.
- 사용이 끊기지 않게 하는 구조: 앱을 한 번 켜 두면 이후에는 화면을 보지 않아도 주행이 기록된다. 다만 부팅 시 자동 실행은 아직 없어, 차량을 다시 켤 때 앱이 유지되는지는 실차에서 확인해야 한다. 이것이 활성 비율을 좌우하는 변수다.
- 효과 검증 방법: 앱이 기기 안에 남기는 기록(최근 200회 주행, 주행마다 민감도·넘침 기준·뒷좌석 탑승 여부 포함)으로 사용 전후를 비교한다. 기록을 전송하지 않으므로 지금은 시험 주행 기기에서 직접 확인하는 범위다. 목표치는 2차 개발의 실차 주행 데이터를 보고 정한다.
  - 주행당 쏟은 횟수의 변화 (도착 리뷰의 지난 주행 비교, 대기 화면의 주행별 추세)
  - 원인별 횟수의 변화 (가장 많던 원인이 줄었는지)
  - 동승자 확인에서 "괜찮았어요"가 나오는 비율 (2차 개발에서 기록 항목으로 추가)

**수익·확대 계획**

- 1단계 (개인): 무료 배포로 사용자 확보. 가족 프로필, 주간 리포트
- 2단계 (사업자): 택시·카셰어링·법인 차량용 승차감 리포트(기사별·차량별)와 "편안한 차량" 인증. 차량 대수 기준 월 구독. 2021~2023년 3년간 새로 등록된 택시 11만 1,583대 가운데 전기택시가 3만 3,400대였다(한국자동차모빌리티산업협회). 지금 앱은 기록을 기기 안에만 두고 전송하지 않으므로, 리포트를 만들려면 기사 동의를 받은 기록 수집, 기사·차량 구분값을 새로 개발해야 한다. 주행마다 그때의 민감도·넘침 기준·뒷좌석 탑승 여부는 이미 함께 남긴다. 리포트 화면 목업(예시 데이터)은 저장소 `docs/사업자-리포트-목업.md`에 있다.
- 3단계 (연계): 운전 습관 연계 보험, 호출 플랫폼의 편안한 차량 표시, 운전 연수 교재 (2단계와 같은 동의·기록 수집이 전제)
- 기능 확대: 회생제동·주행 모드 추천, 동승자 유형별(영유아·임산부·반려동물) 맞춤 기준, 구간별 승차감 지도
